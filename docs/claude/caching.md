# Caching

Moved from CLAUDE.md; loaded on demand.

- **Tracking delta sync** (`app/src/hooks/trackingStore.ts`, logic in `utils/trackingSync.ts`): watchlist tracking pages are saved per user (`TRACKING_PAGE`/`TRACKING_SYNC`) as an exact prefix of Firestore order (priorityDate desc, doc id desc); pages fetched by scrolling stay saved. Launch = saved docs + live listeners on `updatedAt > lastSync` (tracking) and `trackingDeletions` (deletes); full re-fetch of the saved pages once a day. **Every tracking write must carry `updatedAt: serverTimestamp()` and every delete must log `trackingDeletions/{id}`**: clients get it automatically (`utils/stampTrackingWrites.ts` in the platform Firestore wrappers); Cloud Functions use `stampTracking` / `deleteTracking` (`functions/src/shared/trackingSync.ts`; `commitInBatches` stamps tracking refs). Rules hold a written `updatedAt` to `request.time`; anything written without it is stamped server-side by `trackingSyncStamp` (so it never needs to be required). Deletion entries expire via TTL on `expireAt`. There is no stored shows counter (`stats.showsTracking` is legacy, unread): count tracking docs with a `count()` query.
- **Cross-device / server changes already have a channel — don't add refresh flags.** The tracking delta sync above delivers every tracking change (other devices, CFs, backfill scripts); fix a stale cache through it, never with a new `config/app` flag. Local events: `emitShowRemoved` = untracked everywhere (trackedIds, list cards); pausing uses `emitShowPaused` (leaves the watchlist, stays tracked).
- **Previously Watched history is fetched once a day:** the all-titles `useWatchedEpisodes` / `useWatchedMovies` first page is saved per user (`WATCHED_EPISODES_HISTORY` / `WATCHED_MOVIES_HISTORY`, `hooks/watchedHistoryCache.ts`, newest page-size rows only) and restored on launch with `staleTime: Infinity`; marks / unwatches change it via the insert/remove cache helpers, which save it; older pages page by the last row's `lastWatchedAt`. `WATCHLIST_ACTIVE` saves only the Previously Watched rows a cold start has (`utils/watchedHistory.ts` `coldStartHistory`) — a saved row the live list lacked vanished above the view and the list jumped a row.
- Watchlist display list `WATCHLIST_ACTIVE` (daily reorder). `WATCHLIST_EXHAUSTED` = confirmed all tracking pages loaded → footer shows the "all caught up" image at once; otherwise footer is **skeletons, never blank**, until confirmed.
- Catalog: AsyncStorage per show (`CATALOG_SHOW`+docId, index `CATALOG_INDEX`) — Android can't read one AsyncStorage value > ~1M chars ("Row too big for CursorWindow") so split big caches per key. AsyncStorage v3: `getMany/setMany/removeMany`.
- Upcoming invalidates on `lastCatalogSync` change; trending weekly; profile images/weekly activity/completed sections cached.
- Optimistic UI: cancelQueries only if the query already has data; `insertWatched*Cache` create the first page if empty; movie mark keeps `updatingShows` until the listener confirms.
- **Offline:** no blocking overlay — cached screens stay browsable. Every user action that writes or calls a CF (mark / unwatch, add / remove / pause, lists, import / export, account, search submit) starts with `requireOnline()` (`utils/requireOnline.ts`, before any optimistic change): offline (NetInfo / `navigator.onLine` false for `OFFLINE_DELAY_MS`, unknown = online) it opens `NoInternetModal` (app `components/modals`, web `components`) and stops. A new action needs it too. Web preloads the browsable pages' chunks (`AppRoutes`) so they open offline; trending is persisted. Back online (raw offline → online, `utils/reconnectRetry.ts`, wired in `App.tsx` / web `NoInternetModal`) only failed loads retry: active React Query queries with no data that errored (`retryFailedQueries`), and non-RQ loaders through `useRetryOnReconnect(failed, retry)` (Upcoming, Calendar failed months, Watch History first load). Never anything that has data; web has `refetchOnReconnect: false`. A new loader with its own error state should use the hook.
- **Callable priority** (`app/src/services/callQueue.ts`): user-awaited callables (`callCF`, searchTitles) run via `foregroundCall`; self-heal / shared-refresh calls (refreshShow, heal addShow) via `backgroundCall` (at most `NATIVE_CALLABLE_THREADS − FOREGROUND_RESERVED_THREADS` = 3 at once; none start while a foreground call is in flight). Calls are async in JS — the bottleneck is native: RNFirebase Android runs callables on a task executor that defaults to 1 thread, so `firebase.json` `react-native.android_task_executor_maximum_pool_size` must equal `NATIVE_CALLABLE_THREADS` (10; a test checks). A heal burst once queued ~40 refreshShows ahead of a search/add until they timed out.
- **Upcoming keeps watched episodes:** marking an episode watched (any path) only leaves the watchlist's What's Up Next; the `upcoming` doc and the local past-days queue stay. Only untracking / pausing a show removes its Upcoming (`removeShowFromUpcoming`, `clearUpcomingDocs`, removeShow CF, rebuild).
