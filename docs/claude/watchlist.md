# Watchlist, cards, modals, filters

Moved from CLAUDE.md; loaded on demand.

- **Card layout:** watchlist (`ShowCard`, `WatchedEpisodeRow`) and Upcoming (`UpcomingEpisodeRow`) cards share `components/CardInfo` (app) / `web/src/components/CardInfo` + `ShowCard.module.scss` (web): fixed 100-high card (`CARD_RADIUS` corners), title pill / middle line / subline equally spaced by shrinkable gap spacers, so a two-line episode name narrows the gaps instead of growing the card (rows must stay one height). Change the layout there, not per card.
- Episode info modal: `components/modals/EpisodeDetailModal` (app) / `web/src/components/EpisodeDetailModal`. Marking logic lives in `useSeasonActions` (tracking advance, rewatch, "Whoa there Speedster!" backfill via the modal's BackfillModal). Calendar aired episodes open `CalendarScreen/TrackedEpisodeInfo` (drives `useSeasonActions` for one episode); unaired ones open read-only. The modal hides mark buttons for any episode whose `airDate` is in the future.
- **Watchlist render cost:** `ShowCard` / `WatchedEpisodeRow` memo by value (`utils/similarProps.ts`) and card handlers must stay referentially stable (read changing data through refs) — otherwise every rebuilt row / new handler re-renders every card (~1s JS stall per update in dev, several per mark). Don't reuse row objects across recomputes instead: LegendList tracks rows by object and misplaced them (duplicates, missing header). `PosterImage` is keyed by poster path (expo-image kept a stale picture after a quick move-and-back). Off-screen tabs more than one away are frozen (`react-freeze` in `SwipeTabsScreen`; Home never — thawing it desynced the pinned header). Measure with a `React.Profiler` + a rAF gap logger before guessing.
- **Watchlist motion (app):** Reanimated layout transitions / `entering` animations / custom layout worklets on LegendList's recycled containers left views at stale positions (rows on top of each other, blank slots, the header over a card) — never use them. Rows glide instead by a **FLIP patch** in LegendList (`ReanimatedPositionView`): while `itemLayoutAnimation` has a duration (`CARD_LAYOUT` while a list change / mark / unwatch is running, `CARD_LAYOUT_INSTANT` otherwise — the cold-open reorder must not shuffle) the container's `top` stays and a translateY moves it to its new place on the UI thread (it rests at that translate until recycled: a new `top` from React reached the screen frames before the translate, so rows flashed at their new place first); a move under 1 px doesn't restart it (LegendList's measuring corrections ~100 ms in froze the glide); sticky headers glide from the old place unless pinned. Cards joining together (held at launch — aired while the app was closed — or reaching their air time together live) wait in an **entry queue** (`useWatchlistData`): 1 to `WATCHLIST_BULK_CHANGE_CARDS` − 1 come in one at a time, top first (`cardEntryMode` / `cardEntryOrder` in `utils/watchlistOrder.ts`, `CardEntryMode`), each growing in while the rows glide; during a card's run (`CARD_ENTRY_RUN_MS`) the shown list and its promotions count are frozen, so nothing else lands mid-run — a mark / unwatch / live update made meanwhile shows when the run ends, and the next card waits until the list has been still for a run. Launch cards start after the first load (`CARD_RELEASE_QUIET_MS`); everything still waiting after `CARD_ENTRY_MAX_PENDING_MS` comes in at once. Live arrivals from Firestore (another device) aren't queued. Row motion lives in the rows as `useAnimatedStyle` + `withTiming` styles attached for the view's whole life from a value set at mount: a marked row zooms in (`RowZoom`, uniform scale fit to its gap), an unwatched row leaves as a `LeavingGhost` (zooms out over a closing gap), cards entering at air time grow in / flipping cards use `CardMotion`. Key these components by run (`rowZoomKey`, `cardMotionKey`): React re-applies an animated style's initial values on re-render, so a reused one went back to invisible. Never animate a row's height (LegendList doesn't see UI-thread sizes; JS-stepped sizes stall with the JS thread), never drop an animated style mid-run (the view keeps its last pose). Verify with an overlap check over many marks / unwatches, not one recording. Many cards joining / leaving at once (`WATCHLIST_BULK_CHANGE_CARDS`, `isBulkCardChange` in `utils/watchlistOrder.ts`: joined + left between the drawn list and the new one, a launch's saved list included) are a catch-up: one list swap, no `heldCards` hold, no grow-in, glide off (`bulkSwap`). Only a small change animates.
- **Watchlist RefreshControl is always mounted** (switched with `enabled`, never added / removed): on Android a `refreshControl` wraps the native ScrollView, so swapping it in when older Previously Watched pages turned out to exist (~2 s after launch) replaced the ScrollView — it reopened at the initial offset ("What's Up Next", every poster reloading) under a user who had already scrolled. Only showed when scrolling right after a cold open (a fast emulator / late scroll never hit it). Local release builds: Gradle doesn't rebundle JS for `node_modules` / patch changes — delete `android/app/build/generated/assets/createBundleReleaseJsAndAssets` first.
- **Watchlist heals are view-driven:** missing poster / aired next-episode name / movie credits (Firestore re-read, then refreshShow), a missing catalog (addShow) and the aired-without-finale refresh run only for cards that stay on screen `HEAL_VIEW_DWELL_MS` (`useWatchlist().healShown` ← `useHealOnView`; app LegendList `onViewableItemsChanged`, web `useVisibleCards` IntersectionObserver). Never loop heals over every item. "Episode N" titles only count once that episode has aired.
- **Hall of Shame filters:** counts in `users/{uid}/facets/{tv|movie}`, per-title index in `facets/{tv|movie}Index` (title id → `g:`/`c:`/`s:`/`k:` codes, 8 keywords max) written in the same transactions (addShow stamp, removeShow, import, backfillFacets). The drawer lists come from `utils/historyFilterSections.ts` (shared app + web): picks stay, options no title shares with the other sections' picks hide. Accounts without an index doc don't narrow until `backfillFacets` runs. Typed-word aliases (regions, demonyms, genre/keyword synonyms) live in `FILTER_ALIASES` (app enums); the regional part mirrors functions `SEARCH_REGION_ALIASES`.
