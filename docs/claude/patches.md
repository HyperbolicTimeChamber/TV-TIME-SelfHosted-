## Patched dependencies (`app/patches/`, applied by `postinstall: patch-package`)
- **`@legendapp/list` 3.3.5** (`patches/@legendapp+list+3.3.5.patch`): on Android the list turned on the ScrollView's native `maintainVisibleContentPosition` (`minIndexForVisible: 0`). Native MVCP anchors on the first visible *child view*, and LegendList's children are recycled, absolutely-positioned containers in arbitrary order — so after a row was added/removed the scroll followed a random container (the watchlist jumped rows, late, after unwatches / on cold start). The patch turns native MVCP off on Android and makes LegendList apply its own JS anchor adjustments with `scrollTo` (its old-architecture path), and never queues a "pending native adjust" there. That `scrollTo` is deferred two microtasks so it lands with React's commit of the new positions (earlier, one frame showed the list scrolled rows off on cold start). Also patched: the FLIP glide above; sticky headers recompute their push limit on every position change (`lastPositionUpdate` is bumped on all platforms as a counter — with all rows one height a row changing section left `totalSize` equal and the limit stale, so a pushed-off "Previously Watched" pill stayed pinned over the rows) and feed position/limit to the UI worklet through a shared value; pinned header rows are `pointerEvents: box-none` (they swallowed taps on the card under their empty sides). **When updating `@legendapp/list`:** check the changelog / source for Android MVCP changes (`minIndexForVisible`, `requestAdjust`, `shouldQueueNativeMVCPAdjust`); if upstream fixed it, drop the patch, else regenerate it with `npx patch-package @legendapp/list` (look for `PATCH(watchloom)` markers). Then re-test: cold start (no late scroll / one-frame flash), unwatch a Previously Watched row (no jump), mark with "What's Up Next" pinned, mark/unwatch a show's finale while pinned (no stray "Previously Watched" pill), tap a checkmark under a pinned header.
- **`react-native-reanimated` 4.5.0** (`patches/react-native-reanimated+4.5.0.patch`, Android `NativeProxy.kt`): on RN ≥ 0.86 a synchronous prop update to a view committed but not mounted yet threw, and every failure was logged with a full stack trace on the UI thread. Scrolling right after cold open (sticky headers update every frame while the list creates rows) produced ~18k of them → 5–20 s freeze / ANR in release. Backport of the 4.7 fix: skip views `getViewExists` doesn't know (the commit hook applies their props), log one line. **Drop the patch when upgrading to Reanimated ≥ 4.7** (needs `react-native-worklets` 0.13). Regenerate with `npx patch-package react-native-reanimated --exclude '^package\.json$|\.cxx|/build/|\.DS_Store$'` (build artifacts otherwise end up in it). Re-test: cold open, scroll at once, `adb logcat | grep -c "synchronouslyUpdateUIProps failed"` stays ~0, no ANR. Also backported (4.6): settled values reach React's `settledProps` through `AnimatedPropsRegistry::collectSettledUpdates` (synced / invalidated tags) instead of entries aged out after 2 s — a JS stall over that window lost the final value and the next React commit put a stale transform back (a swiped row left off screen, watchlist rows stuck on each other).
- **`react-native-screens` 4.25.2** (`patches/react-native-screens+4.25.2.patch`, Android `NativeProxy` + `cpp/RNSScreenRemovalListener`): backport of upstream PR #4413 (released in 4.28.0). On a cold launch `ScreensModule` set up its mounting override listener from two threads at once (`initialize()` + `onHostResume()`); the racing `shared_ptr` write left React Native holding a freed listener → SIGSEGV on the JS thread in `MountingCoordinator::pullTransaction` (+520 / +524, fault address ASCII or inside `[anon:scudo:primary]`; seen in our dev-client tombstones 15–33 s after start). The listener is now one process-lifetime instance whose callback is swapped in / cleared. **Drop the patch when upgrading to react-native-screens ≥ 4.28.0** (Expo 57 pins `~4.26`). The patch was built from the npm tarball (`npm pack react-native-screens@4.25.2`), not `npx patch-package` (that picks up `android/.cxx` build output).
