# TV Time Revived — project guide for Claude

Self-hosted TV Time clone. React Native (Expo 57) app + React/Vite web app + Firebase (Blaze).
Firebase project `tv-time-returns`. Package `com.tvtimerevived.app` (iOS + Android). Repo `HyperbolicTimeChamber/TV-TIME-SelfHosted-`.
Branches: `web` (active), `newFeatures`, `tmdbProxy`, `development` (base), `staging` (CI: app distribute + web deploy run on push here), `main` (production builds). Version 1.1.0, build 44+.

Read `app/AGENTS.md` too (Expo docs rule, enum rule, typecheck rule). This file is the full context; keep it current when conventions change.

## FIRST: new-machine setup check (ask the user)
On a fresh system, before real work, check whether the tools below exist (`claude plugin list`, `/mcp`, `adb`, `ffmpeg`, Android SDK + `Pixel_9_Pro` AVD). For each **missing** one, **ask the user whether they want it installed** — never install silently.
- **Plugins / skills** used here: `caveman` (terse reply mode — user runs **ultra**), `superpowers` (brainstorming, systematic-debugging, TDD, verification-before-completion, writing-plans, code review…), `design-skills` + `joshus-design-skills` + `native-design` (UI/UX, HIG, Material, RN best practices), `impeccable` (UI design/polish), plus built-ins `commit`, `merge-to-dev`, `code-review`, `simplify`, `run`.
- **MCP servers**: `mobile-mcp` (drive the Android emulator via accessibility tree — preferred over screencap), `playwright` (web testing), `figma` (design↔code), optionally claude.ai Google Drive/Sheets/Docs connectors.
- **CLI**: Android SDK (`adb`, `emulator`, AVD `Pixel_9_Pro`), `ffmpeg` (frame-sheets from user videos), Node 20, Firebase CLI (`firebase deploy`), `gh`.

## Hard rules (user preferences — follow exactly)
- **Reply style:** caveman ultra (terse). Code, commits, PRs, security warnings: write normal.
- **Enums, never string literals** for keys: `src/enums/index.ts` (WatchStatus, MediaType, FreshTag, CacheKey, QueryKey, Route, CloudFunction, DocChangeType). Functions: `functions/src/shared/enums.ts`. Constants/enums go in enums files, not inline.
- **NEVER invalidate/refetch** React Query — always update cache locally (`setQueryData`). Minimise Firestore reads; cache aggressively.
- **Web parity:** every app change must also go to `web/` (web reuses app logic through the `@app/*` alias: hooks, utils, `useSeasonActions`, `useShowDetailActions`, …; UI components are separate). Web tests: `cd web && npm test` + `npx vite build` must pass before pushing.
- **No `Co-Authored-By: Claude` trailer** in commits unless a harness reminder explicitly demands it; follow the user's rule first. Conventional-commit style (`feat(app): …`).
- **Never hide/rename `node_modules` or `.env.local`** to make checks pass.
- **Version bump:** change version only; keep buildNumber/versionCode climbing, never reset to 1 (CI `bump-build.yml` adds +1 per build).
- **Rewatch only when completed:** never set rewatching on incomplete shows; extra E1 counts ≠ rewatch.
- **Verify visuals:** after every UI change, screenshot (+ zoom-crop) on the emulator and judge before reporting.
- **Test against the Firebase Emulator Suite, never production:** before any testing on the Android emulator or localhost web, start `npm run emulators` (seed once with `npm run emulators:seed`) and run the app with `EXPO_PUBLIC_USE_EMULATORS=true` (+ `adb reverse tcp:9099/8080/5001`) / web with `VITE_USE_EMULATORS=true`. Testing on the real account costs ~26k Firestore reads per full reload. Only touch prod data when the user explicitly asks.
- **Emulator safety:** the emulator is signed into a REAL account with real data. Screenshot-confirm the screen before any `adb` swipe/tap that could mark something; use back-key to dismiss confirm modals instead of confirming; avoid card swipes (a fast swipe can become a tap → opens carousel with Mark buttons).
- **Typecheck:** `npx tsc --noEmit` from `app/`, `functions/`, and `web` (`npx tsc -p tsconfig.app.json --noEmit`) — root has no TypeScript. Pre-existing TS error list may be empty now; don't add new ones.
- **LegendList** does not re-render on `extraData` — embed state in data items.
- **Subagent models:** give simple subagents a cheaper model via the Agent `model` param — `haiku` for lookups/greps/file location (Explore), `sonnet` for routine edits/mechanical refactors/test runs. Keep the default (Opus) only for design, debugging, review, or anything needing judgment. Saves context + cost.

## Architecture
- **Shared catalog:** `shows/{docId}` — metadata, seasons/episodes, `trackedBy[]`, `genres[]`.
- **Per-user:** `users/{uid}/tracking`, `watchedEpisodes`, `watchedMovies`, `upcoming`.
- **Config:** `config/app` — `tmdbApiKey` (server-only), `minVersion`, `lastCatalogSync`.
- **Cloud Functions v2** (`functions/src`, `npm run build` then `firebase deploy --only functions`): addShow, removeShow, importMatches, syncCatalog, markSeasonWatched, rebuildUpcoming, deleteAccount (fast: queues `deletionRequests/{uid}` + deletes auth user), purgeUserData (Firestore trigger, europe-west1: recursiveDelete user data in bg; catalog docs kept), testFCM, migrateDocIds, tmdbProxy (guest web HTTP), searchTitles (title search in batches of 5 TMDB pages so the client sorts a whole batch; single instance → global queueing TMDB rate limit + 1h in-memory cache + in-flight dedupe; guests aggregate the same batch from tmdbProxy client-side), sharePreview (OG tags), budgetGuard (Pub/Sub `billing-budget` → unlinks billing when `BILLING_KILL_SWITCH=true`), trackingSyncStamp (Firestore trigger on `users/{uid}/tracking/*`, europe-west1: stamps `updatedAt` on writes that didn't set a new one and logs unlogged deletes — the delta sync safety net for old builds / missed writers). Layout: `shared/` (enums, types/, docId), `hooks/` (subfoldered by calling CF; shared across several → hooks root), `cloudFunctions/`.
- **Abuse limits:** every callable starts with `requireCaller(request, Callable.X)` (`functions/src/hooks/requireCaller.ts`: auth + App Check when `ENFORCE_CALLABLE_APP_CHECK=true` + in-memory per-uid limit from `CALLABLE_RATE_LIMITS`). tmdbProxy: per-IP limit, unknown query params → 400 (cache-busting). `firestore.rules` allowlists the fields clients may add/change per collection — **a new client-written field must be added there too** or writes fail.
- RNFirebase v25 **modular** API (`DocumentSnapshot.exists()` is a method; `GoogleAuthProvider.credential(idToken, idToken)`), React Query, FCM, Crashlytics, Analytics, App Check (app: `src/services/appCheck.ts`, Play Integrity / App Attest, debug provider in dev; web: reCAPTCHA v3; enforcement OFF until the App Check build is widespread).
- TMDB key: signed-in clients read `config/app.tmdbApiKey`; logged-out web uses `tmdbProxy`.
- **Mixpanel** (events + dashboard spec: `docs/analytics/mixpanel-dashboard.md`; project is **EU residency** → send to `api-eu.mixpanel.com`; Free plan = max 5 saved reports per board; token/URLs come from env — `EXPO_PUBLIC_MIXPANEL_*`, `VITE_MIXPANEL_*`, `functions/.env.<projectId>` (gitignored) — never hardcode project values): clients use `app/src/services/mixpanel.ts` (web swaps the SDK via `web/src/platform/mixpanel.ts`). App Firestore / functions imports are redirected by `app/metro.config.js` to `app/src/platform/*` (op counting → `firestore_ops`, callables tagged with `clientPlatform`); web does the same in `web/src/platform/{firestore,functions}.ts`. A **new Cloud Function must use the `tracked*` triggers** from `functions/src/hooks/trackedTriggers.ts`; a new script calls `startScriptMetrics` / `finishScriptMetrics` (`hooks/metrics.ts`). Event names live in `AnalyticsEvent` enums (app + functions).
- App screens: `app/src/screens/{HomeScreen(WatchlistTab,UpcomingTab),CalendarScreen,SearchScreen,ProfileScreen,DetailScreens,ImportDataScreen}`; web mirrors under `web/src/screens`.
- **Card layout:** watchlist (`ShowCard`, `WatchedEpisodeRow`) and Upcoming (`UpcomingEpisodeRow`) cards share `components/CardInfo` (app) / `web/src/components/CardInfo` + `ShowCard.module.scss` (web): fixed 100-high card (`CARD_RADIUS` corners), title pill / middle line / subline equally spaced by shrinkable gap spacers, so a two-line episode name narrows the gaps instead of growing the card (rows must stay one height). Change the layout there, not per card.
- Episode info modal: `components/modals/EpisodeDetailModal` (app) / `web/src/components/EpisodeDetailModal`. Marking logic lives in `useSeasonActions` (tracking advance, rewatch, "Whoa there Speedster!" backfill via the modal's BackfillModal). Calendar aired episodes open `CalendarScreen/TrackedEpisodeInfo` (drives `useSeasonActions` for one episode); unaired ones open read-only. The modal hides mark buttons for any episode whose `airDate` is in the future.

## Caching
- **Tracking delta sync** (`app/src/hooks/trackingStore.ts`, logic in `utils/trackingSync.ts`): watchlist tracking pages are saved per user (`TRACKING_PAGE`/`TRACKING_SYNC`) as an exact prefix of Firestore order (priorityDate desc, doc id desc); pages fetched by scrolling stay saved. Launch = saved docs + live listeners on `updatedAt > lastSync` (tracking) and `trackingDeletions` (deletes); full re-fetch of the saved pages once a day. **Every tracking write must carry `updatedAt: serverTimestamp()` and every delete must log `trackingDeletions/{id}`**: clients get it automatically (`utils/stampTrackingWrites.ts` in the platform Firestore wrappers); Cloud Functions use `stampTracking` / `deleteTracking` (`functions/src/shared/trackingSync.ts`; `commitInBatches` stamps tracking refs). Rules hold a written `updatedAt` to `request.time`; anything written without it is stamped server-side by `trackingSyncStamp` (so it never needs to be required). Deletion entries expire via TTL on `expireAt`. There is no stored shows counter (`stats.showsTracking` is legacy, unread): count tracking docs with a `count()` query.
- **Cross-device / server changes already have a channel — don't add refresh flags.** The tracking delta sync above delivers every tracking change (other devices, CFs, backfill scripts); fix a stale cache through it, never with a new `config/app` flag. Local events: `emitShowRemoved` = untracked everywhere (trackedIds, list cards); pausing uses `emitShowPaused` (leaves the watchlist, stays tracked).
- Watchlist display list `WATCHLIST_ACTIVE` (daily reorder). `WATCHLIST_EXHAUSTED` = confirmed all tracking pages loaded → footer shows the "all caught up" image at once; otherwise footer is **skeletons, never blank**, until confirmed.
- Catalog: AsyncStorage per show (`CATALOG_SHOW`+docId, index `CATALOG_INDEX`) — Android can't read one AsyncStorage value > ~1M chars ("Row too big for CursorWindow") so split big caches per key. AsyncStorage v3: `getMany/setMany/removeMany`.
- Upcoming invalidates on `lastCatalogSync` change; trending weekly; profile images/weekly activity/completed sections cached.
- Optimistic UI: cancelQueries only if the query already has data; `insertWatched*Cache` create the first page if empty; movie mark keeps `updatingShows` until the listener confirms.

- **Callable priority** (`app/src/services/callQueue.ts`): user-awaited callables (`callCF`, searchTitles) run via `foregroundCall`; self-heal / shared-refresh calls (refreshShow, heal addShow) via `backgroundCall` (at most `NATIVE_CALLABLE_THREADS − FOREGROUND_RESERVED_THREADS` = 3 at once; none start while a foreground call is in flight). Calls are async in JS — the bottleneck is native: RNFirebase Android runs callables on a task executor that defaults to 1 thread, so `firebase.json` `react-native.android_task_executor_maximum_pool_size` must equal `NATIVE_CALLABLE_THREADS` (10; a test checks). A heal burst once queued ~40 refreshShows ahead of a search/add until they timed out.
- **Watchlist render cost:** `ShowCard` / `WatchedEpisodeRow` memo by value (`utils/similarProps.ts`) and card handlers must stay referentially stable (read changing data through refs) — otherwise every rebuilt row / new handler re-renders every card (~1s JS stall per update in dev, several per mark). Don't reuse row objects across recomputes instead: LegendList tracks rows by object and misplaced them (duplicates, missing header). `PosterImage` is keyed by poster path (expo-image kept a stale picture after a quick move-and-back). Off-screen tabs more than one away are frozen (`react-freeze` in `SwipeTabsScreen`; Home never — thawing it desynced the pinned header). Measure with a `React.Profiler` + a rAF gap logger before guessing.
- **Watchlist motion (app):** Reanimated layout transitions / `entering` animations / custom layout worklets on LegendList's recycled containers left views at stale positions (rows on top of each other, blank slots, the header over a card) — never use them. Rows glide instead by a **FLIP patch** in LegendList (`ReanimatedPositionView`): the container takes its new `top` at once and a translateY from its old place animates to 0 on the UI thread, only while `itemLayoutAnimation` has a duration (`CARD_LAYOUT` while a list change / mark / unwatch is running, `CARD_LAYOUT_INSTANT` otherwise — the cold-open reorder must not shuffle); sticky headers glide the same way unless pinned. Row motion lives in the rows as `useAnimatedStyle` + `withTiming` styles attached for the view's whole life from a value set at mount: a marked row zooms in (`RowZoom`, uniform scale fit to its gap), an unwatched row leaves as a `LeavingGhost` (zooms out over a closing gap), cards entering at air time grow in / flipping cards use `CardMotion`. Key these components by run (`rowZoomKey`, `cardMotionKey`): React re-applies an animated style's initial values on re-render, so a reused one went back to invisible. Never animate a row's height (LegendList doesn't see UI-thread sizes; JS-stepped sizes stall with the JS thread), never drop an animated style mid-run (the view keeps its last pose). Verify with an overlap check over many marks / unwatches, not one recording.
- **Watchlist heals are view-driven:** missing poster / aired next-episode name / movie credits (Firestore re-read, then refreshShow), a missing catalog (addShow) and the aired-without-finale refresh run only for cards that stay on screen `HEAL_VIEW_DWELL_MS` (`useWatchlist().healShown` ← `useHealOnView`; app LegendList `onViewableItemsChanged`, web `useVisibleCards` IntersectionObserver). Never loop heals over every item. "Episode N" titles only count once that episode has aired.
- **Hall of Shame filters:** counts in `users/{uid}/facets/{tv|movie}`, per-title index in `facets/{tv|movie}Index` (title id → `g:`/`c:`/`s:`/`k:` codes, 8 keywords max) written in the same transactions (addShow stamp, removeShow, import, backfillFacets). The drawer lists come from `utils/historyFilterSections.ts` (shared app + web): picks stay, options no title shares with the other sections' picks hide. Accounts without an index doc don't narrow until `backfillFacets` runs. Typed-word aliases (regions, demonyms, genre/keyword synonyms) live in `FILTER_ALIASES` (app enums); the regional part mirrors functions `SEARCH_REGION_ALIASES`.

## Crashlytics
`App.tsx` enables collection, hooks `ErrorUtils` (JS errors), plugin + gradle plugin present for native crashes (sent on NEXT launch). It does **not** capture Android low-memory-killer SIGKILLs (RAM pressure) — those leave no report. Calendar mode changes leave `crashlytics().log` breadcrumbs. Measured: release build on emulator = ~500 MB total PSS on Home (flat while scrolling the watchlist), calendar resize cycles add ~80 MB over the first ~4 cycles then plateau (~580 MB) — no leak. The earlier 800 MB+ native / 1.2 GB figures were dev-build inflation. A kill under heavy background apps is Android's LMK, not an app bug; it can't be reported. Emulator `/data` was enlarged to 16G (AVD config) because the release APK would not install at 6G.

- App dev: `cd app && npx expo start --dev-client`, `adb reverse tcp:8081 tcp:8081`, open `exp+watchloom://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8081` (scheme `watchloom`; first cold launch may crash once — relaunch). Editing a file can trigger a full reload back to Home.

App: `EXPO_PUBLIC_USE_EMULATORS=true` + `adb reverse` 9099/8080/5001; web: `VITE_USE_EMULATORS=true`. Dev-only (`__DEV__` / `import.meta.env.DEV`).
- **Never full-scan `watchedEpisodes`** (~26k reads): orphan cleanup only runs for shows syncCatalog saw lose episodes (`removedEpisodeShowIds`, `in` queries).
- Web: `cd web && npx vite --port 5199 --strictPort --host 127.0.0.1`; on emulator Chrome use `adb reverse tcp:5199 tcp:5199`. Web taps can lag ~10s — never re-tap Mark. Use the checkmark, not swipe.
- Emulator: AVD `Pixel_9_Pro`; screens at 1280x2856. Prefer mobile-mcp element listing over screenshots; `adb exec-out screencap -p > file.png` otherwise.

## Patched dependencies (`app/patches/`, applied by `postinstall: patch-package`)
- **`@legendapp/list` 3.3.5** (`patches/@legendapp+list+3.3.5.patch`): on Android the list turned on the ScrollView's native `maintainVisibleContentPosition` (`minIndexForVisible: 0`). Native MVCP anchors on the first visible *child view*, and LegendList's children are recycled, absolutely-positioned containers in arbitrary order — so after a row was added/removed the scroll followed a random container (the watchlist jumped rows, late, after unwatches / on cold start). The patch turns native MVCP off on Android and makes LegendList apply its own JS anchor adjustments with `scrollTo` (its old-architecture path), and never queues a "pending native adjust" there. That `scrollTo` is deferred two microtasks so it lands with React's commit of the new positions (earlier, one frame showed the list scrolled rows off on cold start). Also patched: the FLIP glide above; sticky headers recompute their push limit on every position change (`lastPositionUpdate` is bumped on all platforms as a counter — with all rows one height a row changing section left `totalSize` equal and the limit stale, so a pushed-off "Previously Watched" pill stayed pinned over the rows) and feed position/limit to the UI worklet through a shared value; pinned header rows are `pointerEvents: box-none` (they swallowed taps on the card under their empty sides). **When updating `@legendapp/list`:** check the changelog / source for Android MVCP changes (`minIndexForVisible`, `requestAdjust`, `shouldQueueNativeMVCPAdjust`); if upstream fixed it, drop the patch, else regenerate it with `npx patch-package @legendapp/list` (look for `PATCH(watchloom)` markers). Then re-test: cold start (no late scroll / one-frame flash), unwatch a Previously Watched row (no jump), mark with "What's Up Next" pinned, mark/unwatch a show's finale while pinned (no stray "Previously Watched" pill), tap a checkmark under a pinned header.

## Misc gotchas
- **TVMaze air times:** an empty `airtime` means TVMaze's `airstamp` is a 12:00 UTC filler. `hooks/tvmaze.ts` replaces it with the streaming service's release pattern (`STREAMING_RELEASE_TIMES`, e.g. Disney+ 6pm PT) or noon in the studio timezone (`COUNTRY_TIMEZONES`); keep that table current when a service changes its drop time.
- ESLint config uses `tseslint.config()` (v8 API). App icon foreground scaled to 66% safe zone.
- `.claude/settings.local.json` holds local permissions; per-user memory lives outside the repo.
